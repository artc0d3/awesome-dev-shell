# Design: Linux-native OpenSSH agent for Git auth & signing

**Date:** 2026-07-03
**Status:** Approved
**Branch:** `feat/ssh-agent`

## Context

The 1Password SSH-agent bridge (npiperelay → socat → Windows named pipe) has been
removed. It required a Windows-side helper and made the private key awkward to reach
from automated services (coding agents) running inside WSL.

This design replaces it with a **Linux-native OpenSSH agent**, run as a persistent
systemd user service. The user stores their own passphrase-protected key(s) in
`~/.ssh`; the agent holds the decrypted key in memory after a one-time unlock, so
every subsequent Git operation — and any coding agent launched from the shell — can
authenticate and sign without re-entering the passphrase.

The `op-wsl` module keeps the `wslop` (1Password) CLI for secret injection; it no
longer has any SSH responsibility.

## Goals

- Provide SSH auth for Git (cloning/pushing over `git@…`).
- Provide SSH-based Git commit signing.
- Let an unattended coding agent reuse an already-unlocked key with no prompt.
- Stay declarative and platform-agnostic (any Linux with systemd; WSL runs systemd).

## Non-goals

- No passphrase automation (no askpass/1Password unlock helper). Deferred; may be
  revisited later.
- No management of the key files themselves — keys are user-provided at runtime in
  `~/.ssh`, not generated or templated by Nix.
- No `allowed_signers` file generation (see Caveats). Signing/pushing works without it;
  only local signature *verification* needs it.

## Architecture

Two modules cooperate:

### `modules/ssh.nix` (new) — SSH client + agent

Owns the SSH client configuration and the agent lifecycle. Exposes `ads.ssh.enable`.

```nix
config = lib.mkIf cfg.enable {
  services.ssh-agent.enable = true;

  programs.ssh = {
    enable = true;
    addKeysToAgent = "yes";
  };
};
```

- `services.ssh-agent.enable` runs `ssh-agent` as a **systemd user service**,
  persistent across all terminals and independent of any single login session. Home
  Manager also exports `SSH_AUTH_SOCK` (→ `$XDG_RUNTIME_DIR/ssh-agent`) as a session
  variable, which interactive shells — and processes they spawn, including coding
  agents — inherit. This is the mechanism that lets an unattended agent reuse the
  unlocked key.
- `programs.ssh.addKeysToAgent = "yes"` writes `AddKeysToAgent yes` into
  `~/.ssh/config`, so the first Git-over-SSH auth caches the key used for auth in the
  agent for the rest of the boot.

### `modules/dev-tools.nix` (existing) — Git signing

Git config stays consolidated here alongside the existing `programs.git`. The current
`signing.format = null` becomes:

```nix
programs.git.signing = {
  format = "ssh";
  key = "~/.ssh/signing-key.pub";
  signByDefault = true;   # sets commit.gpgSign = true
};
```

Git signs by invoking `ssh-keygen -Y sign`. Given the public-key path, `ssh-keygen`
uses the matching private key from the agent when present, so signing is passphrase-free
once the key is loaded.

### `home.nix`

Add the module import and enable it:

```nix
imports = [ … ./modules/ssh.nix … ];
ads.ssh.enable = true;
```

## Key model

- **Auth key:** user-provided, conventional OpenSSH filename (e.g. `~/.ssh/id_ed25519`).
  Naming is left to the user at runtime; `AddKeysToAgent yes` works with whatever key
  ssh selects — no filename is hardcoded for auth.
- **Signing key:** fixed path `~/.ssh/signing-key` (public half `~/.ssh/signing-key.pub`),
  referenced by `programs.git.signing.key`. May be the same key material as auth or a
  distinct key; the design does not require them to differ.

## Unlock flow (lazy, once per boot)

The systemd agent starts empty on each WSL boot / service restart.

1. After boot, in an interactive terminal, load the key(s) once:
   ```bash
   ssh-add ~/.ssh/id_ed25519 ~/.ssh/signing-key   # prompts passphrase once each
   ssh-add -l                                       # verify loaded
   ```
2. The keys stay in the persistent agent until the next reboot/agent restart.
3. Coding agents launched afterward inherit `SSH_AUTH_SOCK` and use the loaded keys
   with no prompt.

Auth alone can also be unlocked lazily by simply running any `git` op over SSH (thanks
to `AddKeysToAgent yes`); the explicit `ssh-add` above is what guarantees the **signing**
key is loaded, since signing does not self-add (see Caveats).

## Caveats

1. **Signature verification needs `allowed_signers`.** `git log --show-signature` (and
   `git verify-commit`) require a file mapping email → public key, whose content is the
   user's runtime key and so cannot be cleanly generated by Nix. Left out of scope;
   documented as a manual one-liner. Creating/pushing signed commits is unaffected.
2. **Signing does not honor `AddKeysToAgent`.** `ssh-keygen` reads the signing key file
   directly; if the signing key is not already in the agent it prompts for the passphrase
   on every commit and does not cache it. The `ssh-add`-once-after-boot step above avoids
   this. This is expected behavior, documented, not a bug to fix.

## Testing / verification

- `nix build .#homeConfigurations.wsl.activationPackage` evaluates and builds.
- After activation: `systemctl --user status ssh-agent` shows the service active;
  `echo $SSH_AUTH_SOCK` is set; `~/.ssh/config` contains `AddKeysToAgent yes`;
  `git config --get gpg.format` is `ssh` and `commit.gpgsign` is `true`.
